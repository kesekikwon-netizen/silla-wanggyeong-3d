# Strata 3D 설계도 v2 — 경주 문화유산 3D 설명 도구

> **제품 정의 (2026-10-25 사용자 결정)**
> - **Strata** (`hgis`, ka-hgis): 기존 **2D 전용** 앱. 국가유산 자료·보호구역, 조사 파일(.gpkg)·검수, DEM·수치지형도, VWorld, 분석, 도면 스튜디오, 보고서까지 이미 갖췄다.
> - **Strata 3D** (`hgis-3d-engine`, strata-3d.exe): **3D 전용** 앱. 같은 디자인(KaTheme)을 쓰고, **3D 에 관한 모든 것만** 여기에 더한다.
> - 규칙: Strata 에 이미 있는 기능은 다시 만들지 않고 Strata 의 코드·자료를 그대로 가져다 쓴다(KaTheme 처럼 소스를 같이 컴파일하거나, 연동 파이프·조사 파일로 받는다). 아래 장에서 Strata 와 겹치는 부분은 「Strata 재사용 목록」(14장)에 따라 정리한다.

> 작성 2026-10-25. 기준 커밋 `e802de4`.
> 이 문서는 **제품·화면 설계도**다. 구현 지시서(`CLAUDE_CODE_MASTER_PLAN.md`, `SILLA_BANGRI_3D_PLAN.md`)를 대체하지 않고, 그 위에서 "누가 무엇을 하려고 이 화면을 여는가"를 정한다.
> 이 문서가 고치는 것은 아직 아무것도 없다. 완료는 각 단계의 확인 기준(화면 캡처·시험)을 통과했을 때만 말한다.

## 0. 목표를 한 문장으로

**"내가 들어가는 시굴 구역이 경주 신라 유적 전체 속에서 어디에, 무엇과, 어떤 관계로 놓여 있는지"를 3D로 보여 주고, 그 설명이 근거와 함께 남는 도구.**

여기서 나오는 요구:

| 요구 | 뜻 |
|---|---|
| 경주 문화유산 전부 | 국가유산청 지정·등록 + 시·도 지정 + 매장유산 유존지역 + 발굴 유구까지 "한 지도" 위에 |
| 설명 | 화면이 스스로 말하는 것이 아니라, 사용자가 순서와 말을 정해 발표한다 |
| 입지·관계 | 거리·방위만이 아니라 높이차, 보이는지, 같은 방(坊) 안인지, 같은 하천 단구인지, 시대가 겹치는지 |
| 내 시굴 구역 | Strata 조사 파일(.gpkg)의 `survey_area`·`trial_trench`가 주인공이다 |
| 평생 간직 | 프로젝트 파일 하나로 언제 열어도 같은 화면·같은 설명이 다시 나온다 |
| 사람들에게 | 학회·현장설명회·자문회의·일반인 설명에서 그대로 쓴다 |
| 교차검증 | 화면의 모든 것이 출처·정확도·등급을 갖고, 서로 다른 출처끼리 대조한 결과가 보인다 |

## 2. 지금 상태 진단 (2026-10-25, 화면 캡처 `out/window.png`, `out/bangri_window.png` 와 코드 기준)

### 2.1 화면

1. **위쪽 띠에 단추 13개가 한 줄로**: 보기 방식, 높이, 도면 저장 2종, 다시 불러오기, 선 긋기, 격자, 현위치 격자, 지우기, 트렌치, 트렌치 지우기, 글씨±, 창±. 무엇이 주된 일인지 알 수 없다.
2. **같은 기능이 두 곳에**: 선 긋기·격자 만들기가 위쪽 띠와 오른쪽 패널 ③에 모두 있다.
3. **오른쪽 패널이 번호 매긴 입력 양식(①~⑤)**: 유적 바로가기, 20대 유적 켜기, 선·격자, 표시 스위치, 9주5소경 선택이 한 기둥에 쌓여 있다. 길찾기와 설정과 분석이 섞여 있다.
4. **말투가 조용한 도판 규칙과 다르다**: 「✅ … 확인하세요!」, ✏️·📐 이모지, 느낌표. Strata 조용한 도판·ARCHAEO STUDIO 는 이모지와 느낌표를 쓰지 않는다.
5. **상태줄이 개발자용 수치**: 「800×800 칸 … 조각 30개(가장 잘게 10)」. 발표 중 청중에게 보일 내용이 아니다.
6. **평가 표에 「(이름 없음) 유적지(OSM)」 11줄**: 정보가 없는 줄이 이름 있는 유적을 밀어낸다.
7. **트렌치 단면 패널이 늘 화면 1/4을 차지**: 트렌치가 없을 때도, 길이 15 m 일 때(30 m 격자 안이라 평평한 선)도.
8. **설명할 말을 넣을 곳이 없다**: 이름표 문구가 코드에 박혀 있다. 사용자가 고치거나 순서를 정할 수 없다.

### 2.2 신뢰

1. **311개 3D 모델의 표기**: `scripts/generate_gyeongju_heritage_blender.py` 의 `classify_and_build_khs_site()` 는 유형별 틀(석탑·왕릉·사찰…)로 만든 **도식 모델**이다. 화면 배너는 「3D 실측 복원」이라고 쓴다. 전문가 앞에서 가장 먼저 지적받을 부분이다.
2. **지정번호 표기**: 「사적 제6호」「국보 제30호」. 2021-11-19 시행 문화재보호법 시행령·시행규칙 개정으로 지정번호를 표기하지 않는다(「국보 서울 숭례문」). 2024-05-17 국가유산기본법 시행으로 「문화재」는 「국가유산」 체계로, 문화재청은 국가유산청으로 바뀌었다.
3. **DEM 30 m**: Copernicus GLO-30. 경주 분지의 큰 지형은 맞지만 고분 봉분·단구 끝·트렌치 단면에는 거칠다. README 가 이미 밝힌 한계.
4. **트렌치가 저장되지 않는다**: 화면에만 있다. 다시 열면 사라진다.
5. **출처가 화면에 없다**: 도면에는 출처 칸이 있지만, 3D 화면의 이름표·평가 표에는 무엇에서 온 값인지 없다.
6. **대조 결과가 남지 않는다**: OSM–국가유산청 첨성대 1.06 m 일치 같은 대조를 시험에서 했지만, 사용자 화면에서 유적별로 볼 수 없다.

### 2.3 구조

- `MainWindow.cpp` 1,271줄, `BangriDockPanel.cpp` 921줄, `BangriTerrainValidator.cpp` 1,253줄. 화면 만들기·상태·명령이 한 파일에 섞여 있다.
- 설정이 코드 상수다(버퍼 500/1000 m, 이름표 색, 카메라 값, 「미상」 높이 6 m 등). 사용자가 바꿀 수 없고 저장되지 않는다.
- 잘 된 기반은 그대로 쓴다: DEM·LOD 지형, 위성, BVH·k-d 트리, 평가 엔진, HDR 파이프라인, 도면 합성, Strata 파이프 연동, 조사 파일 읽기(`StrataSurvey`).

## 3. 설계 원칙

1. **증거 등급이 모양을 정한다.** 실측·문헌 근거 복원·추정·도식을 화면에서 바로 구분한다(4장). 등급 없는 것은 화면에 올리지 않는다.
2. **사용자가 정한다.** 보이는 것, 이름표 글, 색, 순서, 반경, 단위는 모두 사용자가 바꾸고 저장한다. 앱이 정한 값은 「기본값」으로만 존재하고 언제든 되돌린다.
3. **한 화면에 한 일.** 탐색·분석·발표·도면을 작업 공간으로 나눈다. 같은 기능은 한 곳에만 둔다.
4. **조용한 도판.** Strata `KaTheme` 의 조용한 도판(paperLook) 토큰을 그대로 쓴다: 종이 바탕 `#F5F4ED`, 먹색 `#141413`, 흙색 `#B5573A` 는 화면당 주 단추 하나, 고른 것은 귀리색 `#E3DACC`. 이모지·느낌표 없음. 단추는 하는 일을 짧게.
5. **다시 열면 똑같이.** 프로젝트 파일 하나에 카메라·레이어·설정·장면·트렌치·설명·출처를 모두 담는다. 데이터 내려받은 날짜와 해시도 남긴다.
6. **대조한 것을 보여 준다.** 같은 유적의 서로 다른 출처 좌표·이름을 맞대어 차이(m)를 보이고, 기준을 넘으면 「확인 필요」로 표시한다.
7. **청중을 위한 화면과 나를 위한 화면을 나눈다.** 발표 모드에서는 개발자 수치·도구 띠가 사라진다.

## 4. 증거 등급과 교차검증

### 4.1 등급

| 등급 | 이름 | 예 | 3D 모양 | 이름표 표시 |
|---|---|---|---|---|
| **A** | 실측 | DEM, 위성, 국가유산청 좌표·구역 경계, 내 조사 파일(survey_area·trial_trench·유구), 실측 높이 태그가 있는 건물 | 불투명, 제 색 | 표시 없음(기본) |
| **B** | 근거 복원 | 발굴보고서 치수로 세운 건물지 기단·탑지 (보고서 쪽수 인용) | 불투명, 가는 먹선 외곽 | 「복원·근거」 칩 + 각주 번호 |
| **C** | 추정 복원 | 방리 격자 추정선, 학설에 따른 도로망, 봉분 복원 높이 | 반투명 60 %, 점선 | 「추정」 칩 + 학설 출처 |
| **D** | 도식 | 유형 틀 모델(현재 311개 대부분), 높이 미상 건물 | 반투명 35 % 또는 선화, 회색조 | 「도식」 칩 |

- 범례·도면·발표 화면 모서리에 등급 표가 늘 붙는다(끌 수 있지만 도면에서는 끄지 못한다).
- 지금 311개 모델은 **D로 시작**한다. 사용자가 보고서 치수를 넣고 인용을 달면 B로 올린다(5.6 유산 카드 편집).
- 등급마다 켜고 끄기 따로: 예) "청중에게는 A·B만".

### 4.2 모든 지물이 갖는 출처 기록

```
source        국가유산청 공간정보 / OSM / 내 조사 파일 / 보고서 / 사용자 입력
fetchedAt     내려받은 날짜 (프로젝트 파일에 고정)
crs, accuracy 좌표계와 위치 정확도(알면 m)
citation      보고서·논문 (DBpia nodeId, 쪽수)
tier          A/B/C/D
checks[]      대조 결과 (아래)
```

### 4.3 교차검증 표 (유산마다)

| 대조 | 방법 | 기준 | 결과 표시 |
|---|---|---|---|
| 위치 | 국가유산청 점 ↔ OSM 다각형 중심 ↔ (있으면) 사용자 측량점 | 차이 ≤ 10 m 「일치」, ≤ 50 m 「근접」, 그 밖 「확인 필요」 | 유산 카드에 m 단위 |
| 이름 | 국가유산청 명칭 ↔ OSM name ↔ 원장 표기 | 정규화 후 같음/다름 | 다르면 둘 다 표시 |
| 경계 | 국가유산청 구역 ↔ 위성 판독 | 사용자가 눈으로 확인 체크 | 확인한 날짜 |
| 높이 | 실측 태그 ↔ 층수 ↔ 추정 | 출처 우선순위 | 등급에 반영 |
| 명칭 규칙 | 지정번호 표기 금지(2021-11-19 시행) | 「사적 제6호」 → 「사적 경주 황룡사지」 | 자동 정리 |

「자료에 없음」은 「없음」이 아니라는 README 원칙을 그대로 유지한다. 대조할 출처가 하나뿐이면 「단일 출처」로 쓴다.

### 5.5 관계 카드 / 관계 표 (분석 공간의 핵심)

내 조사구역(또는 트렌치 하나)을 기준으로 모든 유산과의 관계를 한 표로:

| 열 | 계산 | 지금 엔진 |
|---|---|---|
| 거리 | 구역 경계 ↔ 유산 경계 최단 거리 (중심 거리 아님) | 점 기준만 있음 → 보강 |
| 방위 | 16방위 + 도 | 있음 |
| 높이차 | 표고 차, 내 구역이 위/아래 | 있음 |
| 같은 방(坊) | 추정 방리 격자 셀이 같은지, 몇 칸 떨어졌는지 | 격자 엔진 있음 → 연결 |
| 지형 단위 | 같은 단구·선상지·구하도 쪽인지 (TPI·Weiss 분류) | 분류 있음 → 연결 |
| 하천 | 북천·남천·형산강까지 거리, 같은 쪽 기슭인지 | 없음 → 추가 |
| 시대 | 유산 시대 ↔ 사용자가 넣은 조사 예상 시대 | 없음 → 유산 카드에 시대 칸 |
| 등급 | 그 유산 자료의 등급 | 4장 |

- 표 위에서 줄을 고르면 3D 화면에 두 곳을 잇는 선과 거리 글이 뜬다.
- 「발표에 넣기」로 그 관계가 장면 하나가 된다.

### 5.6 발표 공간과 장면(이야기)

- **장면** = 카메라 위치 + 켠 레이어 + 강조한 지물 + 제목 + 말(본문 3~5줄) + 근거 각주 + 넘김 방식(날아가기/바로).
- 장면 띠(아래)에서 끌어 순서 바꾸기, 복제, 지우기.
- **재생**: 전체 화면, 도구 띠·상태줄 사라짐, ← → 로 넘김, 장면 사이 카메라가 부드럽게 이동, 큰 글씨(발표 글씨 크기 따로 설정).
- **강조**: 고른 지물 외 모두 옅게(불투명 25 %), 고른 것은 흙색 외곽선.
- **비교**: 지금 위성 ↔ 복원(방리·건물) 가로 막대로 밀어 비교.
- **레이저**: 마우스 대신 둥근 표시가 지형 위에 붙는다.
- 기본 이야기 하나를 만들어 둔다: 「경주 전체 → 왕경 중심 → 월성·황룡사 → 내 시굴 구역 → 트렌치 단면」. 사용자가 고친다.

### 5.7 도면 공간

- 지금 `SheetComposer` 를 틀(템플릿)로 나눈다: 입지도(A3 가로), 조감도(A4), 단면도, 방리 5패널.
- 모든 틀에 자동으로: 축척 막대, 방위표, 좌표계, 범례(등급 포함), 출처 표, 만든 날, 프로젝트 파일 이름.
- 이미지 내보내기: 현재 화면을 원하는 크기(최대 8K)로. 영상 내보내기: 장면 경로를 프레임으로 렌더해 저장(동영상 묶기 도구는 구현 전에 OSGeo4W 안에서 쓸 수 있는지 확인).

## 7. 프로젝트 파일 — 평생 간직

`이름.s3d` (JSON, 사람이 읽을 수 있게) + 같은 폴더 `이름.s3d.data/`

```
version, createdAt, app version
survey      { gpkgPath, sha256 }           조사 원본은 읽기 전용, 해시로 바뀜 확인
trenches[]  { id, 점들, 이름, 메모 }         내가 그린 트렌치·선·격자 (원본 gpkg 와 별도)
camera, bookmarks[]
layers[]    { id, visible, style }
settings    { 6장의 프로젝트 설정 }
heritage overrides[] { id, 이름표 글, 설명, 인용, 등급, 치수 }
stories[]   { 장면들 }
sources[]   { 이름, URL, 받은 날, sha256, 정확도 }   DEM·위성·국가유산청 받은 것
```

- `.s3d.data/` 에 받은 DEM·위성·벡터 사본을 둔다(「자료 묶어 저장」을 켜면). 인터넷이 없어도, 10년 뒤 서비스가 바뀌어도 같은 화면.
- 트렌치는 Strata 조사 파일과 **좌표가 같은** GeoJSON 으로도 내보낸다(Strata 로 돌려보내기는 연동 명령으로, 원본을 고치지 않고 새 레이어로).

## 10. 단계

| 단계 | 내용 | 확인 기준 |
|---|---|---|
| **1. 뼈대·신뢰** | 작업공간 4개 + 레이어 트리 + 유산 카드 + 설정 창(6장 전 항목 중 지금 엔진에 있는 것) + 프로젝트 파일 + 등급 A–D 그리기 + 지정번호 표기 정리 + 말투 정리 + MainWindow 쪼개기 | 전체 창 캡처 4장(공간마다), 프로젝트 저장→닫기→열기 후 같은 화면 캡처 비교, 설정 기본값 되돌리기 시험 |
| **2. 내 조사와 관계** | 조사 파일 레이어 트리 연결, 트렌치 저장, 관계 표(경계 거리·같은 방·지형 단위·하천), 교차검증 표 | 실제 조사 gpkg 로 관계 표 캡처, 대조 결과를 손 계산(GDAL·QGIS)과 비교 |
| **3. 발표** | 장면·장면 띠·재생·강조·비교·기본 이야기 | 재생 중 캡처 5장, 장면 저장 후 다시 열어 같은지 |
| **4. 도면·영상** | 도면 틀 분리, 8K 이미지, 장면 경로 영상 | 출력 파일 열어 눈으로 확인 |
| **5. 고해상도 자료** | 내 DEM·드론 정사영상·사진측량 메시·가우시안 스플랫 불러오기, 국가유산청 3D 자료 확인 | 실제 파일로 불러온 캡처, 좌표 대조 |

각 단계는 「눈으로 본 것·시험으로 확인한 것만 완료」 원칙을 따른다.

## 12. 설계 근거 반영 (2026-10-25, DBpia 대화 1583715 D01~D08 → `docs/research/DESIGN_BASIS.md`)

DBpia AI 답이다. 원문 확인 전까지는 「방향을 정하는 근거」로만 쓰고 수치를 사실로 넣지 않는다.

| 설계 항목 | 바뀌거나 확인된 것 | 근거 |
|---|---|---|
| 4장 등급 표현 | 불투명도 + 선 모양(점선) 방향 유지, **흐림은 쓰지 않음**. 색만으로 구분하지 않고 이름표 칩을 겹침. 선 굵기 구분은 검토 | D04 |
| 4장 범례 | 도면에서 끌 수 없는 규칙 유지(실제·가설 데이터 시각 구분 요구) | D04·D06 런던 헌장·세비야 원칙 |
| 4.2 출처 기록 | **파라데이터 칸 추가**: 근거 종류(문헌/발굴보고서/비교 사례), 가설, 결정한 사람, 날짜, 불확실성 | D05·D06 |
| 5.5 관계 표 | 지금 열(거리·방위·높이차·같은 방·지형 단위·하천·시대)이 연구 사례와 대응 → **하천 열 확정**. 방위는 16방위와 도 함께 | D07 |
| 5.5 표 주석 | 높이차·하천은 **현재** 지형 기준(북천 바닥은 신라기보다 약 4 m 낮아짐) | D07, F06 |
| 5.6 발표 | 장면 글은 키워드 중심, 요약 → 「더 보기」로 유산 카드. 비교 막대는 「대상」·「배경」 두 방식. **전문가용·일반인용 이야기 두 벌** | D03·D01 |
| 5.7 도면 틀 | 방위표·축척 막대·좌표계·**기준점 2점 이상** 표기. 자문회의 틀 = 위치도 + 주변 유적 분포도 + 배치도 + 단면도 + 사진 칸. 바탕은 1:5,000 수치지도 / DEM 음영 선택 | D02·D08 |
| 5.2 작업 공간 | 분석 = 여러 칸, 발표 = 단순 화면 분리 확인. 화면 말은 GIS 용어를 풀어 씀 | D01·D02 |
| 7장 프로젝트 파일 | 받은 날·해시·정확도·좌표계 기록, 자료 사본 묶기가 사업 간 형식 비호환·노후화 대응이 됨(형식 자체 근거는 없음) | D05·D06 |

열린 문제(근거 미확인 또는 충돌):
- 등급 표현에서 「신호등 색이 수치 기억에 가장 좋다」와 「불투명도가 가장 좋다」가 서로 다름 → 원문 확인 전까지 불투명도+선+칩 조합 유지.
- 신라왕경 디지털 복원 사업의 구성·연동은 확인되지 않음(D05 인용 주제 의심) → 연동을 전제하지 않음.
- 국가유산청 도면 작성 지침 원문은 직접 확인하지 못함.

## 13. 앱에 필요한 정보 반영 (2026-10-25, DBpia 대화 1583715·1583745 E01~E12 → `docs/research/APP_NEEDS.md`)

### 원칙 — 근거가 확인되지 않은 수치는 「판정 기준」으로 코드에 박지 않는다
- 역사문화환경 보존지역 500 m, 지표조사 3만 ㎡, 시굴 10 % 같은 **법령 수치는 답에 조문 인용이 없다** → 앱은 「설정값 + 근거 조문 칸」으로만 받고, 조문을 사람이 넣기 전에는 「근거 미확인」으로 보인다.
- 북천 옛 바닥 높이 보정은 답 안에서 방향이 엇갈린다(E05) → 기본값으로 넣지 않는다.
- 레이어 분류(성격 8종 × 시기 4종)는 출처가 없다(E01) → 「앱 규약」으로 표시하고 사용자가 고칠 수 있게 한다.
